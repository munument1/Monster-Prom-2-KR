# Monster Camp 번역·검수 기준

## 작업 범위

`python extract_catalog.py`로 설치본의 원문을 `work/catalog.jsonl`에 추출합니다. 번역은 `translations/*_ko.json`에 원문 카탈로그의 **전체 ID → 한국어 텍스트** 형태로 기록합니다. UI 문구만 짧은 원본 키를 사용할 수 있지만, 새 작업은 전체 ID를 권장합니다.

기존 번역 JSON을 검사하여 ID가 겹치는지 확인하고, 구간을 분할할 때는 같은 원문을 두 번 번역하지 않습니다. `work/`, `build/` 및 실제 게임 파일은 Git에 포함하지 않습니다. 번역 중간에 원문 에셋을 덮어쓰지 않습니다.

**Windows PowerShell 5 주의:** Python 표준 입력으로 한글 포함 here-string을 파이프할 때는 기본 `$OutputEncoding`으로 인해 모든 한글이 `?`로 변할 수 있습니다. 가능하면 파일 쓰기 도구로 UTF-8 텍스트를 직접 저장합니다. 반드시 파이프를 사용한다면 먼저 다음을 설정하세요.

```powershell
$OutputEncoding = [Console]::OutputEncoding = New-Object System.Text.UTF8Encoding($false)
```

파일 생성 직후 실제 한글 음절이 존재하는지 확인합니다. `build_preview.py`는 값이 5개 이상인 파일에서 한글 음절이 하나도 없는 경우 손상으로 판단하여 중단합니다. 정상 JSON 형식과 정상 변수 검사만으로는 `???` 텍스트 손상을 찾아내지 못합니다.

대사에서 인물 이름의 풀네임이 처음 나오는 문맥이면 성을 살리고, 친근한 부름말에서는 이름이나 별칭을 자연스럽게 씁니다. 의도적으로 영어로 된 상품명·유명 브랜드·고유명사는 고유명사의 성격을 고려해 표기하고, 맥락상 필요한 경우 뜻이 드러나는 한국어로 풉니다.

플레이어 아바타를 색으로 지칭할 때는 식별자 `빨강`, `노랑`, `초록`, `파랑`을 씁니다. 조사 때문에 색 이름이 어색하게 읽히면 `빨강 쪽이`처럼 문장을 풀어 씁니다. 사물·피부·빛깔을 설명하는 일반적인 색 표현은 문맥에 맞춰 `빨간`, `노란`, `초록`, `파란` 등으로 옮깁니다.

`%CURRENTPLAYERNAME%`과 `%CURRENTPLAYERNAMECAPS%`는 이 네 아바타 이름 중 하나로 치환됩니다. 따라서 바로 뒤에 조사가 붙으면 받침 있는 이름에 맞춰 `이/은/을/과/이랑/으로`를 사용합니다. 문장이 부자연스러우면 이름 뒤에 조사를 억지로 붙이지 말고 문장 구조를 바꿉니다.

## 말투와 농담

- **지문/서술자:** 영어의 `you`를 한국어의 `너`로 자연스럽게 유지하고, 사건 묘사는 `~한다`, `~했어` 등 문맥에 맞춰 일관되게 표현합니다. 게임 속 짓궂은 농담과 메타 농담을 지우지 않습니다.
- **데미안:** 거친 반말, 욕설과 과장된 흥분. 대사의 코미디를 무디게 만들지 않습니다.
- **캘큘레스터:** 대체로 정중하고 논리적인 존댓말. 컴퓨터·기계 관련 개그와 과도한 분석적 표현을 유지합니다.
- **마일로:** 매끄럽고 장난스럽고 유혹적인 어조. 상대에게 `자기` 같은 호칭을 쓸 수 있습니다.
- **캐릭터·나레이터:** 동일 이벤트 안에서 화자가 바뀌는 위치를 원문 주변 행에서 확인합니다.

성적 농담·욕설·블랙 코미디는 게임의 문맥에 맞게 번역합니다. 문자 그대로 옮기면 한국어에서 개그가 성립하지 않는 언어유희는 뜻과 웃음의 구조를 살려 재구성합니다.

## 구조와 변수

- `%CURRENTPLAYERNAME%`, `%ICEBREAKERPLAYERS%`, `%HESHE%`, `%WEEKS%` 같은 `%...%` 변수는 원형·횟수 모두 유지합니다.
- `%GOSSIPQUALITY_RUN_DRY[sp]HUMP%`처럼 변숫값 안에 `[sp]`가 있는 복합 변수는 **전체를 하나의 변수**로 취급해 정확히 보존합니다.
- `[n]`, `[sub]`, `[/sub]`, `[0]` 등의 제어 태그·치환 토큰은 횟수와 형태를 유지합니다. 실제 탭·캐리지리턴·개행 문자는 번역 JSON 값에 넣지 않습니다.
- 이벤트의 ID, 선택지 번호, 성공·실패 분기 이름과 스크립트 메타데이터는 변경하지 않습니다. `+2` 등 능력치 수치와 부호는 그대로 둡니다.
- 능력치 변화는 `대담함 +2`, `창의력 +1`, `지능 -2`처럼 한국어 이름과 원래 부호·숫자로 표기합니다. `+2BOLDNESS`처럼 영문 코드가 게임 대사에 노출되지 않게 하고, 수치 뒤의 조사도 한국어 문장에 맞춥니다.
- 원문과 완전히 같은 값 또는 빈 번역은 검증기가 오류로 취급합니다. 숫자만 있는 UI 값처럼 번역할 필요가 없는 항목은 JSON에서 제외해 게임 원문을 유지합니다.

## 검증과 적용

```powershell
python .\build_preview.py
python .\build_mod.py
python .\report_progress.py
```

이 검사는 번역 키의 정확성·변수 및 서식 토큰 보존·문자열 재적용 구조를 검증합니다. **의미 번역 정확성이나 게임 화면에서의 글자 잘림까지 보장하지 않습니다.** 폰트·줄바꿈·모드 활성화는 실제 게임에서 별도로 확인합니다.

게임 이벤트 중 ID가 아예 없는 19개 원문 행은 `Localization.txt`에 바로 대응할 공식 키가 없습니다. 번역 JSON과 미리보기에는 포함할 수 있지만, `build_mod.py`는 이 행을 내보내지 않고 `manifest.json`의 `requires_asset_patch`에 기록합니다. 다른 자산 패치 방식이 검증되기 전까지는 게임 표시 여부가 확인되지 않은 상태입니다.
